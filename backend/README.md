# Backend - Supabase Configuration

This folder contains all backend-related configuration for the PatientVoice Healthcare Feedback System.

## Architecture

**Backend Type:** Supabase (Backend-as-a-Service)
- **Database:** PostgreSQL hosted on Supabase
- **Authentication:** Supabase Auth
- **Real-time:** Supabase Realtime subscriptions
- **Storage:** Supabase Storage (for file uploads)
- **APIs:** Auto-generated REST APIs from Supabase

## Files in this folder:

### 1. `supabase-schema.sql`
Complete PostgreSQL database schema including:
- 8 tables (profiles, departments, feedback, responses, attachments, tags, reports, audit_logs)
- Indexes for performance optimization
- Row Level Security (RLS) policies
- Triggers for auto-updating fields
- Functions for business logic
- Seed data for departments

**Usage:**
- Copy this entire file
- Paste into Supabase SQL Editor
- Execute to create all database structures

### 2. `SUPABASE_SETUP.md`
Step-by-step guide to set up Supabase backend:
- Creating a Supabase project
- Configuring authentication
- Running the schema
- Setting up storage buckets
- Configuring environment variables
- Testing the connection

### 3. `.env.example`
Template for environment variables:
```env
VITE_SUPABASE_URL=your-project-url.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
```

**Important:** 
- Copy this to `.env` in the root directory
- Add your actual Supabase credentials
- Never commit `.env` to Git

## How to Set Up

1. **Create Supabase Account**
   - Go to https://supabase.com
   - Sign up / Log in
   - Create a new project

2. **Get Credentials**
   - Go to Settings > API
   - Copy Project URL and anon key

3. **Configure Environment**
   - Copy `.env.example` to root as `.env`
   - Add your Supabase URL and key

4. **Run Database Schema**
   - Open Supabase SQL Editor
   - Paste contents of `supabase-schema.sql`
   - Execute query

5. **Test Connection**
   - Start frontend: `npm run dev`
   - Try logging in
   - Check console for errors

## Database Structure

### Core Tables:
- **profiles** - User profiles (extends Supabase auth)
- **departments** - Hospital departments
- **feedback** - Patient feedback submissions
- **feedback_responses** - Staff responses to feedback
- **feedback_attachments** - File uploads
- **feedback_tags** - Categorization tags
- **reports** - Saved/scheduled reports
- **audit_logs** - System activity tracking

### Key Features:
- ✅ Auto-generated feedback numbers (FB-2024-001)
- ✅ Auto-calculated overall ratings
- ✅ Sentiment analysis storage
- ✅ Priority levels and status tracking
- ✅ Row-level security for data access
- ✅ Audit trail for compliance

## API Endpoints (Auto-generated by Supabase)

All tables automatically get REST endpoints:
- `GET /rest/v1/feedback` - List feedback
- `POST /rest/v1/feedback` - Create feedback
- `PATCH /rest/v1/feedback?id=eq.{id}` - Update feedback
- `DELETE /rest/v1/feedback?id=eq.{id}` - Delete feedback

**Note:** Row-level security automatically filters data based on user permissions.

## Real-time Subscriptions

Subscribe to database changes:
```javascript
supabase
  .channel('feedback_changes')
  .on('postgres_changes', { 
    event: '*', 
    schema: 'public', 
    table: 'feedback' 
  }, (payload) => {
    console.log('Change:', payload);
  })
  .subscribe();
```

## Security Features

1. **Row Level Security (RLS)**: Enabled on all tables
2. **JWT Authentication**: Automatic with Supabase Auth
3. **API Key Protection**: Anon key is safe for client-side use
4. **HTTPS**: All connections encrypted
5. **Audit Logging**: All actions tracked
